## 2. 멀티플레이어를 검토했다가 철회한 경위

다음 세션이 같은 논의를 처음부터 반복하지 않도록 경위와 근거를 남긴다.

### 2.1 발단

PM이 보드게임 벤치마크 기획안(「실리콘 팹」 — Brass: Birmingham / Kanban EV / Silicon Valley /
Acquire의 메커니즘을 메모리 반도체 테마로 이식)을 가져왔다. 7개 축으로 구성된 안이었다:
네트워크 타일 경제 · 폴리오미노 R&D 퍼즐 · 부서 워커플레이스먼트 · 수율 백빌딩 ·
HBM/TSV 리듬게임 · 강제 M&A · 거시 이벤트 카드.

이 중 M&A와 네트워크 타일 충돌은 **여러 사람이 같은 보드에서 부딪혀야 성립하는 메커니즘**이라,
당시 PM은 "진짜 멀티플레이어로 전환 + H-002(30~40분) 폐기"를 일단 결정했다.

### 2.2 철회 근거

**Codex 측** (`benchmark-integration-v0.1.md`, 원작 공식 규칙서를 직접 확인):

- 원작 플레이타임: Brass: Birmingham 60~120분, Kanban EV 90~120분, Silicon Valley 60~120분.
  7축을 전부 독립 미니게임으로 유지하면 현실적 예상은 **120~180분**.
- "10년 동안 한 회사를 경영하고 회고한다"는 현재 제품 약속과 **강제 M&A가 정면 충돌**한다
  (긴 세션 중 플레이어 탈락 위험 포함).
- 물리적으로 네트워크가 접촉했다는 이유로 기업이 합병되는 것은 산업 현실과도 맞지 않는다.
- PM이 제공한 기획안 자체의 결함도 지적: 수율 로지스틱 함수가 붙여넣기 과정에서 누락되어
  **수치 모델을 재현할 수 없고**, 참고문헌에 비공식 요약·공략이 섞여 있다. → 밸런스 근거로 쓸 수 없고
  "재미 후보 라이브러리"로만 사용해야 한다.

**PM 측**:

> "멀티플레이어는 상대방이 없으면 AI가 프로그램을 짜야 하는데 그건 정말 난이도가 높을 것 같거든"

→ 최종 결정: **싱글플레이어(또는 오토마) 유지, 로컬, 혼자서도 플레이 가능해야 함.**

### 2.3 중요 — 롤백할 코드는 없었다

멀티플레이어는 **논의만 됐고 단 한 줄도 구현되지 않았다.** `src/core.js`는 처음부터 끝까지
"플레이어 1 + AI 3사" 구조 그대로였다. 따라서 이 철회는 코드 롤백이 아니라 **문서상 결정의 정정**이다.

## 3. 이미 존재하는 오토마 자산

PM이 우려한 "AI를 새로 짜야 하는 난이도"는 **기존 레버 범위에서는 이미 해결돼 있다.**
향후 "오토마를 처음부터 만들어야 하나?" 하는 혼선을 막기 위해 현재 구현 상태를 명시한다.

`src/core.js`의 `aiDecide(c, s, rng)`가 작동하는 오토마다:

- **5개 행동편향**으로 각 경쟁사 성격이 갈린다 —
  관성(`inertia`) / 점유율집착(`shareObsession`) / 자만(`overconfidence`) /
  손실회피(`lossAversion`) / 정치제약(`politicalConstraint`).
- **관성 기반 간헐 재평가**: `reevalInterval = 1 + round(inertia × 5)`. 관성이 높은 회사는 최대
  6분기까지 기존 정책을 유지하다가 재평가한다. 현금 위기(`cash < capacity × 1.5`) 시에는 관성을
  무시하고 강제 재평가.
- **국면 반응**: 루즈/균형 국면에서 적자면 감산하되, 감산 의지는
  `(1-손실회피) × (1-정치제약×0.7) × (1-점유율집착×0.5)`로 계산된다. 정치제약이 0.6을 넘는
  회사는 적자여도 가동률 75% 아래로 못 내려간다.
- **증설·노드 전환·HBM 배분**을 각자 판단한다. 노드 전환 욕구는
  `리더와의 격차×0.25 + 자만×0.3 + (1-관성)×0.2`.

즉 **40턴 완주 가능한 상대가 이미 3사 존재한다.** 남은 과제는 "오토마를 만드는 것"이 아니라,
새 메커니즘(예: 부서 보드, 공유 슬롯)을 도입할 때 그에 맞춰 **오토마를 확장하는 것**이다.

한계도 함께 기록한다: 진영별 행동편향 초기값은 실측 근거가 없는 추정치다(원본 v0.3 §5 수치를
확보하지 못함 — `README.md`와 `worklog.md`에 기록된 기존 한계).

## 4. BM 7축 — 싱글플레이어 기준 재판정

Codex의 판정표(`benchmark-integration-v0.1.md` §3)는 대부분 유효하나, 그중 일부는 **멀티플레이어
가능성을 전제로 "별도 모드 후보"로 열어둔 것**이었다. 싱글플레이어가 확정된 지금 그 항목들의
지위가 달라지므로 재정리한다.

| BM 축 | Codex 판정 | 싱글 확정 후 지위 |
|---|---|---|
| 산업 타일 뒤집기 | 우선 반영 | **유지** — 프로젝트 완료 시 앞면→결과면 전환. 싱글에서도 그대로 유효 |
| 부서별 보드 | 우선 반영 | **유지** — 화면 구획으로만. 워커 선점 규칙은 넣지 않음 |
| 제한된 행동력 | 이미 반영 | **유지** — 분기당 3개 결정(D-003)이 이미 같은 긴장 |
| Develop(구세대 제거) | 표현만 반영 | **유지** — 노드 전환을 구세대→신세대 타일 전환으로 표현 |
| Innovator·2nd Mover | 후속 실험 | **유지** — 경쟁 AI 대비 선착 여부를 회고 배지로. 점수화는 S2 이후 |
| 거시 이벤트 카드 | 표현만 반영 | **유지** — 기존 시대·정권을 카드로 공개. 새 랜덤 보정치는 추가하지 않음 |
| 16비트 픽셀·물리 질감 | 아트 실험 | **유지** — 타일·토큰·카드에 한정. 가독성/색각 검증 후 확장 |
| 수율 백빌딩 | 보류 | **보류 유지** — 현 수율은 결정론적이라 추첨 연출을 붙이면 거짓 인과가 됨 |
| 폴리오미노 R&D | 보류 | **보류 유지** — 단, 붙인다면 노드 전환이 아니라 **제품·패키지 설계**에 (Codex 2차 의견) |
| HBM 리듬게임 | 기본 루프 반려 | **제외 확정** — 손기술이 전략 결과를 덮으면 사후 설명성이 깨짐. 양측 일치 |
| 글로벌 공급망·3자원 | 확장팩 후보 | **범위 밖** — 두 번째 경제 엔진. 싱글에서 병목 경쟁의 의미가 약함 |
| 네트워크 타일 경쟁 | 핵심 후보(멀티 전제) | **범위 밖** — 멀티 전용. 후속 프로젝트로 분리 |
| M&A·네트워크 합병 | 별도 모드 후보 | **범위 밖** — 멀티 전용. 후속 프로젝트로 분리 |
| 지출 기반 턴 순서 | 현재 비적합 | **범위 밖** — 분기 동시 정산 구조에 순서 경쟁이 없음 |

**요약**: 싱글에서 살아남는 것은 **표현·상태·기다림·완료 보상** 계열이고, 사라지는 것은
**플레이어 간 충돌** 계열이다. 이는 Codex가 §1에서 내린 결론("첫 통합 대상은 새로운 경제 규칙이
아니라 현재 규칙을 손으로 만지는 듯 이해하게 만드는 상태 표현")과 일치한다.

## 5. H-002(세션 길이) — 미결로 남기는 이유

이번 라운드에서 PM은 "코덱스 권장: 3축 집중형(75~90분)"을 선택했다. **다만 그 질문은 멀티플레이어
전제로 제시된 것**이었고(공유 병목 네트워크 경쟁이 핵심 축에 포함된 상태), 같은 답변 묶음에서
멀티플레이어가 철회됐다.

따라서 현재 상태는 다음과 같다:

- 원래 승인값: **30~40분** (H-002, 싱글 전제)
- 멀티 전환 논의 중: 사실상 폐기
- 멀티 철회 후: **다시 미정**

싱글플레이어에서 네트워크 경쟁·M&A가 빠지면 게임의 무게가 줄어들므로, 75~90분이 여전히 맞는지
재확인이 필요하다. **임의로 정하지 않고 PM 결정 항목으로 남긴다.**

이 값이 정해져야 다음이 결정된다:
- 40턴 유지 여부 (30~40분이면 턴당 45~60초, 75~90분이면 턴당 2분 내외)
- Fab Operations Board(BM-002)의 정보 밀도와 연출 길이
- 플레이테스트 세션 설계(`playtest-plan-v0.1.md`의 45분 세션 전제)
