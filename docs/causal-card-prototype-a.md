# 분기 결과 인과 카드 — Codex 시안 A

> 작업 ID: `P-001-A`
> 설계: `Codex`
> 비교 시안: Claude의 시안 B
> 데이터 계약: `docs/trace-schema-v0.1.md`
> 상태: 화면 설계 완료, A-004 브랜드명 확정 전 UI 구현 보류

## 1. 설계 목표

턴 종료 뒤 5초 안에 플레이어가 다음 세 문장에 답하게 한다.

1. 이번 분기에 가장 크게 바뀐 결과는 무엇인가?
2. 내 어떤 결정과 시장·경쟁사 변화가 그 결과를 만들었는가?
3. 과거 결정 중 아직 끝나지 않은 것은 언제 다시 영향을 주는가?

시안 A의 핵심은 **한 결과를 먼저 보여주고, 원인을 세 줄로 압축한 뒤 필요할 때만 펼치는 것**이다.
전체 계산표나 뉴스 피드를 기본 화면에 넣지 않는다.

## 2. 기본 카드 구조

```text
┌─────────────────────────────────────────────────────┐
│  2031 Q2 결과                         [현금][이익][ASP] │
│                                                     │
│  현금  -312                         전분기 대비 -4.8% │
│                                                     │
│  1  내 결정   T3 노드 전환 투자             -180  직접 │
│     9분기 남음                                      │
│  2  시장      ASP -8.4%로 매출 감소          ↓96  추정 │
│  3  경쟁사    {{FACTION_NAME_2}}·{{FACTION_NAME_4}}  정황 │
│              공급 증가가 가격 압박                       │
│                                                     │
│  다음 영향  증설 D-04 · 2분기 뒤 완공               │
│                                      [계산 펼치기 ▾] │
└─────────────────────────────────────────────────────┘
```

실제 문구와 숫자는 trace fixture에서 생성한다. 위 수치는 레이아웃 예시일 뿐 기준선으로 쓰지 않는다.
진영 표시명은 하드코딩하지 않고 `actorId`를 브랜드 사전에서 해석한다. A-004 승인 전에는
`{{FACTION_NAME_1}}`~`{{FACTION_NAME_4}}` 플레이스홀더만 사용한다.

## 3. 정보 계층

### 1단계 — 자동 노출

- 기본 결과 하나: 절대 변화가 크거나 위기 임계값을 넘긴 `cash`, `operating_income`, `price` 중 하나.
- 이전 분기 대비 값과 방향.
- 영향도가 큰 원인 최대 3개: `decision`, `market`, `competitor`를 우선하고 필요한 경우 `system` 포함.
- 진행 중 장기 프로젝트 가운데 완료가 가장 가까운 것 하나.

### 2단계 — 결과 탭

`현금`, `이익`, `ASP` 탭을 바꾸면 같은 `QuarterTrace`의 다른 `OutcomeTrace`를 본다. 탭 이동은 카드를
닫거나 게임 진행을 막지 않는다.

### 3단계 — 계산 펼치기

- 현금: 영업이익, capex, 이자 등 `exact` 가산 분해.
- ASP: 정권, 공급압력, 노이즈의 로그수익률 분해.
- 원인을 선택하면 최초 결정 턴, 예상·실제 완료 턴, 중간 프로젝트 상태를 한 줄 타임라인으로 표시.

## 4. 원인 표현 규칙

| trace 근거 | 카드 표기 | 숫자 사용 |
|---|---|---|
| `exact` | `직접` | 실제 기여값 표시 |
| `modeled` | `추정` | 모델이 산출한 경우에만 값 표시, 아니면 방향만 |
| `context_only` | `정황` | 숫자·백분율 금지 |

캐주얼 유저에게 “confidence”라는 용어를 노출하지 않는다. `직접/추정/정황`은 색만이 아니라 텍스트와
선 모양으로 구분한다. 원인 문장은 다음 구조를 유지한다.

```text
[주체] + [행동/사건] + [결과 방향] + [시차]
```

예: `T3에 승인한 노드 전환 투자로 이번 분기 현금 180 감소 · 9분기 남음`.

## 5. 과거 결정과 미래 예고 분리

- **이번 결과** 영역에는 이미 정산된 영향만 둔다.
- **다음 영향** 영역에는 예상 완료 턴과 예정 효과만 둔다.
- 예정값은 결과 기여액처럼 표시하지 않고 `예상` 꼬리표를 붙인다.
- 실제 완료가 예상 턴과 달라지면 기존 결정을 덮어쓰지 않고 `expectedCompletionTurn`과
  `actualCompletionTurn`을 함께 보여준다.

이 구분은 “지금 낸 capex”와 “6분기 뒤 들어오는 capacity”를 한 효과처럼 오해하지 않게 한다.

## 6. 시장 설명 안전장치

- D-001 전에는 `balanceSignal.kind=implied_from_price`를 “실제 Sufficiency”나 “수요 대비 공급”이라고
  쓰지 않는다.
- 대신 `공급 증가율이 시대 기준을 웃돌아 ASP를 압박`처럼 직접 계산된 항만 설명한다.
- 정권 prior는 `시장 사이클`, 공급압력은 `업계 공급`, noise는 기본 카드에서 숨기고 상세 계산에만 둔다.
- P0-E 테스트를 통과하지 못하면 ASP 인과 카드를 표시하지 않고 개발 모드 오류로 처리한다.

## 7. 상호작용

1. 턴 정산 직후 화면 오른쪽 결과 영역에 카드가 나타난다.
2. 키보드 초점은 강제로 이동하지 않으며, `Esc`로 접고 다시 열 수 있다.
3. 원인 행을 누르면 연결된 결정·프로젝트가 기존 화면에서 강조된다.
4. `다음 분기` 버튼은 카드를 읽지 않아도 누를 수 있다.
5. 위기·완공·퀄 통과처럼 중요한 사건만 최초 한 번 자동 확장한다.

모바일 폭에서는 원인 세 줄을 세로로 유지하고 결과 탭은 가로 스크롤 없이 3등분한다.

## 8. 시안 B와 공통 비교 조건

두 시안은 같은 고정 시드와 같은 `trace-v0.1` fixture를 사용한다. 비교 때는 스타일 취향보다 아래 과제를
먼저 본다.

| 기준 | 측정 질문 | 1차 통과 기준 |
|---|---|---|
| 5초 이해 | 가장 큰 결과와 원인을 바로 말할 수 있는가 | 5명 중 4명 정확 |
| 과거 결정 회상 | 원인 결정의 최초 턴을 찾는가 | 10초 안에 찾음 |
| 미래/결과 구분 | 예정 효과를 이미 난 결과로 오해하지 않는가 | 오해 20% 이하 |
| 인과 정확성 | 카드 설명이 trace와 일치하는가 | fixture 전건 일치 |
| 정보 밀도 | 다음 턴 진행을 방해하지 않는가 | “복잡하다” 2/5 이하 |
| 재확인성 | 닫은 카드를 다시 찾을 수 있는가 | 도움 없이 성공 |

## 10. 완료 기준

- 현금·이익·ASP 결과 탭이 동일 fixture에서 렌더링된다.
- `직접/추정/정황` 표기 규칙을 위반하지 않는다.
- 원인 행에서 결정·프로젝트 턴으로 이동할 수 있다.
- 320px 폭과 키보드만 사용한 흐름에서 정보 손실이 없다.
- `node build.js`와 기준선 검증을 통과한다.
- Claude 시안 B와 함께 PM이 바로 비교할 수 있는 실행 링크 또는 단일 HTML을 제공한다.
