# 인수인계 프롬프트 — DRAM 사이클 시뮬레이터 v0.2 구현 착수

아래를 그대로 Claude Code / Codex 세션에 붙여넣어 시작한다. 이 프롬프트는 자기완결적이며, 별도 컨텍스트 없이 이 내용만으로 구현을 시작할 수 있어야 한다.

---

## 프로젝트 개요

DRAM(메모리 반도체) 사이클 경영 시뮬레이션 게임. 플레이어는 SK하이닉스/삼성/마이크론/CXMT 중 하나가 되어 10년(분기 턴 40턴) 동안 노드 전환·증설·수율 투자·HBM 배분 결정을 내리고, 결과는 시장 가격 사이클과 경쟁사 반응에 좌우된다. 단일 HTML 파일(바닐라 JS, 외부 프레임워크 없음)로 구현한다. 기존에 두 개의 프로토타입이 이미 존재한다:

1. **시장 엔진 프로토타입**: 12년/연턴/레버4개짜리 구버전. 국면 없이 단일 지수 함수였음. 이번 v0.2는 이걸 대체하는 것이지 확장하는 게 아니다.
2. **팹 시각화 프로토타입**(`fab-lifecycle-pixel.html`): 픽셀 아트로 부지정지→골조→외장→클린룸→장비반입→파일럿→양산의 7단계를 캔버스 애니메이션으로 그린 것. 이 파일의 캔버스 렌더링 패턴(단계별 오버레이, HUD 게이지)을 재사용하되, 노드/제품 무관하게 팹 외형은 고정하고 **라인 내부 색상 팔레트만 세대별로 스왑**하는 방식으로 확장할 것.

## 필수 참고 문서
같은 대화에서 생성된 `DRAM-sim-design-v0.4.md`(최종 설계 문서)를 반드시 먼저 읽어라. 이번 프롬프트는 그 문서의 실행 지침이며, 두 문서가 충돌하면 이 프롬프트를 따르되 왜 충돌했는지 사용자에게 보고할 것.

## v0.2 스코프 — 반드시 이것만 구현할 것

**넣을 것 (4개 시스템):**
1. 시장 엔진: 국면 분류(Sufficiency 1축, 4국면) + 국면별 반응함수 + 국면 지속기간의 비대칭
2. 생산성 엔진: `Saleable Bit = Wafer Starts × Gross Bit/Wafer(노드) × FE Yield × HBM Trade Penalty × BE Yield`, 노드 전환 시 Ramp Valley(일시적 Saleable Bit 하락) 포함
3. 믹스 엔진: 고객 티어 3단(프리미엄/표준/채널) 게이팅, 티어 진입은 노드 수준+퀄 상태로 결정, 다운빈은 자동으로 하위 티어로 흘러감
4. 경쟁 AI 3사: 5개 행동편향 파라미터(관성/점유율집착/자만/손실회피/정치제약) 기반, 분기마다 재계산하지 말고 관성만큼 이전 결정 유지

**넣지 말 것 (v0.3 이후로 명시적으로 보류된 것들):**
- 진영별로 다른 승리조건 — 단일 Score 공식 + 진영 가중치만 사용(아래 산식 그대로)
- LTA 캡 선택, 계약가/스팟가 이중 트랙 — 이번 버전은 국면 기반 단일 가격만
- Cross-impact Matrix, 리딩 인디케이터 라이브러리 UI — 안 만든다
- 국면별로 다른 탄력성 지수 — 국면상수만 다르고 지수(b=2.7)는 공통
- NAND, 지정학 이벤트, EUV 슬롯 예약 시스템 — 전부 v0.4 이후

레버가 6개(증설/노드전환/수율투자/HBM배분/가동률/현금관리)를 넘으면 설계를 벗어난 것이니 멈추고 재확인해라.

## 정확한 파라미터 값 (실측 캘리브레이션 완료, 재추정하지 말고 그대로 쓸 것)

### 시장 엔진
```
국면 분류 (Sufficiency = Supply/Demand):
  극단타이트: Sufficiency < 0.97   → 분기 가격변동 국면상수 +11.1%
  타이트:     0.97 ≤ S < 1.00      → 국면상수 +5.1%
  균형:       1.00 ≤ S < 1.03      → 국면상수 -2.7%
  루즈:       S ≥ 1.03             → 국면상수 -16.1%

반응함수: ΔlnP = 국면상수 + 2.7 × (-ln(Sufficiency))

국면 지속기간 (분기 단위로 환산, 원 데이터는 월 단위):
  하락국면: 중앙값 5분기(16개월), 범위 2~12분기, 사이클 총 변동 중앙값 -53.5%
  상승국면: 중앙값 3분기(8개월),  범위 2~8분기,  사이클 총 변동 중앙값 +23.2% (꼬리 최대 +141%, 확률적으로 드물게 큰 상승 허용할 것)

시대 프리셋 (캠페인 시작 시 택1 또는 10년 중 1회 전환 이벤트):
  성숙기:      ASP -25~-35%/yr,  bit출하 +55~75%/yr
  성장둔화기:  ASP -16%/yr,      bit출하 +26%/yr
  AI슈퍼사이클: ASP +10.6%/yr,   bit출하 +17%/yr
```

### 생산성 엔진
```
Ramp Valley: 노드 전환 승인 후 2분기간 Saleable Bit이 기준 대비 -15%~-25% (구현 시 -20% 고정값으로 시작, 추후 난이도 파라미터화)
HBM Wafer Trade Penalty: HBM 배분 웨이퍼는 동일 웨이퍼 대비 컨벤셔널의 1/3.5 bit만 산출 (범위 3~4배, 3.5 고정값 시작)
노드 전환 리드타임: 승인 후 3년(12분기) 뒤 신규 Gross Bit/Wafer 적용 시작
```

### 믹스 엔진
```
티어1(프리미엄, HBM/서버 LTA): 기준가 대비 +400~600% (HBM 한정), 진입조건 = 선단노드 보유 AND 퀄 통과
티어2(표준): 기준가 그대로, 진입조건 = 양산노드 보유
티어3(채널): 기준가 대비 -8~-18%, 진입조건 없음(누구나 여기로 밀어낼 수 있음)
다운빈 규칙: 수율 미달분은 자동으로 티어3 물량으로 산입
```

### 승리 조건
```
Score = 누적(분기 영업이익 - 자본비용) + w1 × 진영별_전략지표 - 파산페널티

진영별_전략지표 (w1 = 1.3 공통):
  SK하이닉스: HBM 매출 비중
  삼성:       총 bit 점유율
  마이크론:   ROIC(자본비용 대비 초과수익률)
  CXMT:       국내고객 매출비중 + 메이저 대비 노드격차 축소분

파산 페널티: 순현금 4분기 연속 마이너스 → 강제 종료, 그 시점 Score로 확정
```

### 경쟁 AI 5개 행동편향 (0~1 스케일, 진영별 초기값은 설계 문서 v0.3 5절 참고해 이식할 것 — 이번 문서엔 재수록하지 않았으니 대화 히스토리 또는 사용자에게 재확인)
```
관성(inertia): 과거 결정 유지 경향
점유율집착(share_obsession): 적자에도 물량 방어
자만(overconfidence): 호황 지속 신념→고점 증설
손실회피(loss_aversion): 감산 지연
정치제약(political_constraint): 비경제적 가동 유지(CXMT 강함)
```

## 아키텍처 지침

- 순수 JS 시뮬레이션 코어(`runQuarter(state, decisions) → newState`)를 UI 렌더링과 완전히 분리해라. 이전 프로토타입에서 이 분리 덕분에 Node.js로 몬테카를로 검증이 가능했다 — 이번에도 반드시 유지.
- 코어 로직을 `<script>` 태그 안에 `// ==SIM_START==` / `// ==SIM_END==` 주석으로 감싸서, 검증 스크립트가 `sed`로 추출해 별도 실행할 수 있게 해라(이전 프로토타입 관례).
- 구현 후 반드시: (1) 13개 이상 시드 × 5개 이상 고정 전략으로 지배전략 부재 검증, (2) 4사 중 특정 진영이 Score 분포를 일관되게 지배하지 않는지 검증. 결과를 콘솔 로그로 출력하고 사용자에게 요약 보고할 것.
- UI는 기존 두 프로토타입의 시각 언어(모노스페이스 폰트, 국면색상 petrol/loss/gain, 그리드 배경)를 유지해라 — 새 스타일을 만들지 말 것.

## 완료 정의 (Definition of Done for v0.2)

1. 브라우저에서 40턴을 끝까지 플레이 가능
2. 노드 전환을 언제 할지가 실제로 고민되는 순간이 3~5년차(턴 12~20)에 발생하는지 자가 점검하고 보고
3. 몬테카를로 검증 결과(지배전략 부재, 진영 균형) 로그 첨부
4. `/mnt/user-data/outputs/`에 최종 HTML 저장 및 `present_files`로 제시

## 시작하기 전에 확인할 것

이 스코프가 너무 크면(예: 하루 작업량을 넘으면) 먼저 "생산성 엔진 + 시장 엔진"만으로 극소 프로토타입을 만들어 노드 전환 타이밍 고민이 실제로 발생하는지부터 검증하고, 통과하면 믹스 엔진과 AI를 얹는 순서로 진행해도 된다. 순서를 바꾸는 건 허용하되 스코프 자체를 넘는 것은 안 된다.
