# 가상 진영 브랜드명 초안 v0.1

> 작업 ID: `A-004`
> 초안: `Codex`
> 최종 승인: `PM`
> 상태: 1차 수정 제안 — PM 승인 및 상표 검토 전 사용 금지

## 제안 원칙

- 실제 기업·국가명을 직접 연상시키는 단어를 피한다.
- 한 단어로 쓰고 한국어로 읽었을 때 진영끼리 발음이 겹치지 않게 한다.
- 모든 진영에 3자 이하의 고유 코드를 부여해 작은 카드·차트에서도 즉시 구분한다.
- 회사의 플레이 성향은 암시하되 이름만으로 정답 전략을 노출하지 않는다.
- 내부 식별자는 `FACTION_1`~`FACTION_4`로 유지해 표시명 교체가 저장 데이터와 trace를 깨지 않게 한다.
- 아래 이름은 창작 후보이며 상표·법인명·도메인 가용성을 보증하지 않는다.

## 1차 권장 세트

| 내부 ID | 한 단어 이름 | 한글 표시 | 3자 코드 | 의도 |
|---|---|---|---|---|
| `FACTION_1` | Helix | 헬릭스 | `HLX` | 선단 기술과 적층 메모리의 기술 집약 인상 |
| `FACTION_2` | Atlas | 아틀라스 | `ATL` | 대규모 생산 기반과 묵직한 시장 존재감 |
| `FACTION_3` | Mira | 미라 | `MIR` | 절제된 투자와 효율 중심의 안정적 인상 |
| `FACTION_4` | Nova | 노바 | `NVA` | 빠르게 격차를 좁히는 도전자와 확장성 인상 |

이름을 짧고 직관적으로 만든 만큼 다른 산업의 기존 상표와 충돌할 가능성이 있다. 현재 단계에서는 게임 내
가독성 후보로만 사용하며, PM이 세트를 채택한 뒤 출시 대상 국가의 상표·법인명·도메인을 별도로 확인한다.

## 문서·코드 적용 전 플레이스홀더

PM 승인 전에는 다음 값만 사용한다.

```text
{{FACTION_NAME_1}}
{{FACTION_NAME_2}}
{{FACTION_NAME_3}}
{{FACTION_NAME_4}}

{{FACTION_CODE_1}}
{{FACTION_CODE_2}}
{{FACTION_CODE_3}}
{{FACTION_CODE_4}}
```

trace와 저장 데이터에는 표시명이나 코드를 넣지 않고 `FACTION_1`~`FACTION_4`를 기록한다. UI가 현재
로케일의 표시명·코드 사전에서 값을 가져오면 향후 작명 변경이나 번역이 게임 기록을 깨지 않는다.
작은 카드·차트·경쟁사 마커에는 3자 코드를 기본 노출하고, 상세 패널과 문장형 카피에는 전체 이름을 쓴다.

## PM 검토 질문

1. 네 이름과 3자 코드를 한 세트로 채택할지, 일부만 남길지.
2. 한글 표시를 그대로 쓸지 영문 단어만 노출할지.
3. 출시 전 별도 상표 검토를 어느 단계에서 진행할지.

승인 전에는 A-COMP-001 에셋 제작과 S4 인과 카드 UI 구현을 시작하지 않는다.
