# 가상 진영 브랜드명 초안 v0.1

> 작업 ID: `A-004`
> 초안: `Codex`
> 최종 승인: `PM`
> 상태: 제안 — PM 승인 및 상표 검토 전 사용 금지

## 제안 원칙

- 실제 기업·국가명을 직접 연상시키는 단어를 피한다.
- 한국어로 읽었을 때 진영끼리 발음이 겹치지 않게 한다.
- 회사의 플레이 성향은 암시하되 이름만으로 정답 전략을 노출하지 않는다.
- 내부 식별자는 `FACTION_1`~`FACTION_4`로 유지해 표시명 교체가 저장 데이터와 trace를 깨지 않게 한다.
- 아래 이름은 창작 후보이며 상표·법인명·도메인 가용성을 보증하지 않는다.

## 1차 권장 세트

| 내부 ID | 영문 표시명 | 한글 표시명 | 짧은 표시 | 의도 |
|---|---|---|---|---|
| `FACTION_1` | VetraStack Memory | 베트라스택 메모리 | 베트라스택 | 선단 패키징과 고대역폭 제품에 강한 기술 집약 인상 |
| `FACTION_2` | Auralith Semiconductor | 오라리스 세미컨덕터 | 오라리스 | 대규모 생산 기반과 묵직한 시장 존재감 |
| `FACTION_3` | Caelora Memory | 케일로라 메모리 | 케일로라 | 절제된 투자와 효율 중심의 안정적 인상 |
| `FACTION_4` | Orivex Semiconductor | 오리벡스 세미컨덕터 | 오리벡스 | 빠르게 격차를 좁히는 도전자와 확장성 인상 |

네 이름은 1차 웹 중복 확인에서 동일한 반도체 회사명 조합을 찾지 못한 후보만 남겼다. 이는 정식 상표
검색이 아니며, PM이 세트를 채택한 뒤 출시 대상 국가의 상표·법인명·도메인을 별도로 확인해야 한다.

## 문서·코드 적용 전 플레이스홀더

PM 승인 전에는 다음 값만 사용한다.

```text
{{FACTION_NAME_1}}
{{FACTION_NAME_2}}
{{FACTION_NAME_3}}
{{FACTION_NAME_4}}
```

trace와 저장 데이터에는 표시명이 아니라 `FACTION_1`~`FACTION_4`를 기록한다. UI가 현재 로케일의
표시명 사전에서 이름을 가져오면 향후 작명 변경이나 번역이 게임 기록을 깨지 않는다.

## PM 검토 질문

1. 네 이름을 한 세트로 채택할지, 일부만 남길지.
2. 플레이어에게 법인 전체명과 짧은 표시 중 무엇을 기본 노출할지.
3. 현실 산업극에 가까운 톤과 미래 기업극에 가까운 톤 중 어느 쪽으로 한 단계 조정할지.

승인 전에는 A-COMP-001 에셋 제작과 S4 인과 카드 UI 구현을 시작하지 않는다.
