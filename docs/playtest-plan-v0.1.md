## 2. 참가자와 세션

- 1차 6명: 반도체 비전문 전략게임 유저 3명, 반도체 지식 보유자 3명.
- 권장 세션 45분: 소개 3분, 플레이 30~35분, 회고 인터뷰 7~10분.
- 진행자는 규칙을 대신 결정해주지 않고, 참가자가 소리 내어 생각하도록 요청한다.
- 모든 참가자는 같은 진영·시대에서 시작하되 고정 시드는 최소 2종을 번갈아 배정한다.

플레이 시간이 H-002에서 다르게 확정되면 세션 길이와 턴 연출을 함께 조정한다.

## 3. 테스트 시나리오

### 시드 A — 하락 후 회복

- 목적: 현금 방어와 장기 투자의 긴장 확인.
- 관찰: 감산을 늦추는지, 노드 전환을 취소하고 싶은지, 회복 시 물량 부족을 이해하는지.

### 시드 B — 짧은 상승과 급락

- 목적: 상승 카운트다운과 고점 증설 유혹 확인.
- 관찰: 추격 증설, HBM 과배분, 경쟁사 신호 해석.

실제 시드 번호는 C-001 기준선 생성 뒤 Claude Code가 재현 결과와 함께 지정한다.

## 4. 기록할 이벤트

```text
session_started(faction, era, seed)
decision_staged(turn, lever, before, after)
decision_reverted(turn, lever)
quarter_committed(turn, decisions[])
project_started(type, expected_turn)
project_completed(type, actual_turn)
market_phase_changed(from, to)
financial_crisis_started(turn)
company_bankrupt(company, turn)
game_finished(turn, score, bankrupt)
```

각 장기 프로젝트에는 결정 ID를 부여해 완료·재무·시장 사건과 연결한다. 실제 원격 텔레메트리는 별도 동의 전
추가하지 않고, 1차 테스트는 로컬 JSON 내보내기와 관찰 기록지로 진행한다.

## 5. 진행자 질문

### 플레이 중

1. 지금 가장 걱정되는 수치는 무엇인가?
2. 이 결정을 내리면 언제 어떤 결과가 올 것으로 예상하는가?
3. 경쟁사는 다음 분기에 무엇을 할 것 같은가?
4. 방금 결과는 어떤 이전 결정에서 왔다고 생각하는가?

### 종료 후

1. 가장 후회되는 결정과 가장 만족스러운 결정은 무엇인가?
2. 노드 전환을 고민하기 시작한 시점과 실제 승인 시점은 언제였나?
3. HBM 배분에서 무엇을 포기했다고 느꼈나?
4. 이해되지 않거나 억울하게 느껴진 결과는 무엇인가?
5. 한 판 더 한다면 무엇을 다르게 하겠는가?

## 7. 1차 판정

- PT-01 또는 PT-03이 실패하면 신규 콘텐츠를 추가하지 않고 핵심 루프와 피드백을 먼저 수정한다.
