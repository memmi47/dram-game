순서만 정하고 결론은 미뤘는지를 한 곳에 정리한다. 근거의 원문은 위 4개 문서에 있으므로 여기서는
**결과만** 표로 남긴다.

## 2. 검증을 거쳐 正이 물러선 것

Codex의 감사(`design-audit-v0.2-v0.4.md`)가 요청한 재현 검증을 Claude가 전부 실행한 결과, P0-A~E
5건 모두 실제 결함으로 확인됐다(그중 P0-E는 Claude가 검증 과정에서 발견). 상세는
`plan-claude-response.md` §1~3, `tools/audit-repro.js` 참고.

- **"v0.2는 완성된 룰셋"이라는 正의 전제 철회.** 反의 "검증 근거 부족" 판단이 맞았다.
- **反의 0순위(P0 결함을 실패 테스트로 잠그기)를 正의 1순위(인과 가시화)보다 앞에 둔다.** P0-E를
  두고 인과 UI를 먼저 만들었다면 "증설했더니 가격이 올랐다"는 잘못된 설명을 성실하게 생성했을 것.
- **첫 병행 프로토타입 주제**: 正이 제안한 팹 비주얼(작업 편의 기준) → 反이 제안한 인과 카드(핵심
  재미 직결, 외부 에셋 불필요)로 확정. PM이 `worklog.md`(P-001)에서 승인.

## 3. 순서에 합의하고 결론은 미룬 것 (D-001)

시장 엔진의 진실 원천 — 反은 "제약된 하이브리드"(Supply/Demand 기반 + 정권 prior)로 재설계할 것을
제안했고, 正은 방향에는 동의하되 지금 재설계하면 v0.2 개발 초기의 가격 폭주 회귀와 모델 변경 효과를
구분할 수 없다고 반론했다. 反이 独자적으로 재검증 후 동의:

> "하이브리드는 실제 Supply/Demand를 진실 원천으로 되돌리는 설계 변경이다. 방향에는 여전히
> 동의하지만, 비교 장치 없이 먼저 구현하면 폭주 회귀와 모델 변경 효과를 구분할 수 없다."
> — `plan-codex-response.md`

**합의된 순서**: P0 수정(S0~S1) → 고정 시드 fixture(S2) → 현재 엔진 vs 하이브리드 A/B(S6 이전) →
PM이 채택 여부 결정. 이번 v0.5 기획서 확정에는 **포함하지 않는다** — S6에서 별도 결정 사안으로 남긴다.

## 4. 부수 발견 — 원래 없던 5번째 항목 (P0-E)

正이 D-001을 정량화하려다가 `capacityPressure` 부호 반전을 발견했다(공급 증설이 가격을 올리는
반경제적 버그, 14시드 중 9건에서 재현). 反이 독립 재검증하고 수정 방향에 동의, 단 "부호만 고치고
시대별 상수(`ERA_TILT`)는 같은 커밋에서 건드리지 말 것"을 조건으로 걸었다. 正이 그대로 반영해
S0을 완료했다(커밋 `79ccf4f`). 부호 수정만으로 전략간 평균 격차 466%→243%, 파산율 47%→30%로
개선 — 反이 지적한 지배전략 미입증 WARN의 상당 부분이 이 버그였음이 사후적으로 확인됐다.

## 6. H-004 반영 — 두 에이전트 권고와 다른 결정, 후속 작업 필요

Claude와 Codex 둘 다 "실명 유지 + 공식 로고만 보류"를 권고했으나, PM은 **가상 브랜드명으로 전면
교체**를 선택했다. 정-반-합에서 두 에이전트가 합의했다고 PM 결정이 거기 갇히지 않는다는 걸 보여주는
사례라 기록해둔다. 이 결정은 하위 작업에 즉시 영향을 준다:

- `src/core.js`의 `FACTIONS` 배열(`SK하이닉스`/`삼성전자`/`마이크론`/`CXMT` 실명) 전면 교체 필요.
- `docs/asset-spec-v0.1.md`의 A-COMP-001(경쟁사 마커)이 "실명 유지" 전제로 쓰여 있어 갱신 필요.
- `docs/causal-card-prototype-a.md` 등 카피가 실명을 참조한다면 함께 갱신 필요.
- 신규 가상 브랜드명 4종 제작이 새 작업 항목으로 추가됨. Codex가 1차 초안을 맡고 PM이 승인한다 —
  `docs/brand-name-proposals-v0.1.md`, §7 참고.

## 8. 결론

정-반-합 절차 자체는 여기서 종료한다 — 남은 항목(D-001, D-005, 브랜드명 작명)은 새로운 반론이
있어서가 아니라 **아직 측정·제작할 근거가 없어서** 미뤄진 것이므로, 별도 토론 없이 해당 단계
(S6, S2, 브랜드 작업)에서 정상적으로 처리한다. 이번 합의 결과는 `docs/design-v0.5.md`(최종
기획서)와 `docs/decision-register-v0.1.md`에 반영했다.
