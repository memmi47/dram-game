# dram-game

DRAM 사이클 경영 시뮬레이터 v0.2 — 단일 HTML 파일(바닐라 JS)로 구현된 4분기×10년(40턴) 경영 시뮬레이션.
SK하이닉스 / 삼성전자 / 마이크론 / CXMT 중 한 진영을 맡아 노드 전환·증설·수율 투자·HBM 배분·가동률·현금 관리를
결정하고, 결과는 국면 기반 시장 가격과 3사 AI 경쟁사의 반응에 좌우된다.

`docs/handoff-prompt-v0.2.md`와 `docs/design-v0.4.md` 두 문서의 실행 지침을 따른 구현체이다.
프로젝트 작업 이력(무엇을 언제 누가 왜 했는지)은 `docs/worklog.md`에 시간순으로 기록하고,
팀 역할 분담·에셋 목록·게임성 전략 등 현재 계획은 `docs/team-plan.md`에서 관리한다.

## 실행

```
open index.html   # 또는 브라우저에서 파일을 직접 연다. 서버/빌드 불필요.
```

## 검증

```
node validate.js
```

`index.html`의 `// ==SIM_START==` ~ `// ==SIM_END==` 사이 순수 시뮬레이션 코어를 추출해 Node.js에서
15개 시드 × 5개 고정 전략(균형형/HBM올인/물량방어/보수적생존/공격증설) × 4개 진영으로 몬테카를로를
돌리고, 지배 전략 부재·진영 균형·파산율·노드 전환 타이밍을 콘솔에 리포트한다.

## 아키텍처

- **시뮬레이션 코어** (`runQuarter(state, decisions, rng) → newState`): DOM에 의존하지 않는 순수 함수.
  `state`는 JSON-직렬화 가능한 평범한 객체이므로 `JSON.parse(JSON.stringify(state))`로 매 턴 복제한다.
  `index.html` 안에 `// ==SIM_START==` / `// ==SIM_END==` 주석으로 감싸 `validate.js`가 그대로
  추출해 Node에서 재사용한다(프로토타입 관례 유지).
- **UI 레이어**: 코어 위에서 상태를 그리기만 한다. 캔버스 팹 시각화(팹 실루엣은 고정, 라인 색상은
  노드 세대 팔레트 스왑, HBM 배분 시 자주색 포드, Ramp Valley 중 조명 플리커), 국면 배지, 가격 미니 차트,
  6개 레버(턴당 최대 3개 결정 강제), 경쟁사 요약 패널로 구성.

## 구현된 4개 시스템 (v0.2 스코프)

1. **시장 엔진** — Sufficiency 1축 4국면 분류 + 반응함수(`ΔlnP = k(국면) + 2.7×(-ln Sufficiency)`).
   국면 지속기간의 비대칭(하락 중앙값 5분기/−53.5%, 상승 중앙값 3분기/+23.2%, 꼬리 최대 +141%)은
   정권(regime)별로 **총 누적 변동을 직접 샘플링**해 해당 정권의 분기 수에 고르게 분배하는 방식으로
   구현했다 — 아래 "설계 과정에서 발견한 문제와 수정" 참고.
2. **생산성 엔진** — `Saleable Bit = Wafer Starts × Gross Bit/Wafer(노드) × Yield × HBM Trade Penalty(1/3.5)`,
   노드 전환 12분기 리드타임 + 전환 직후 2분기 Ramp Valley(-20%).
3. **믹스 엔진** — 티어1(HBM, 선단노드-1 이내+퀄 통과, 기준가×5) / 티어2(표준) / 티어3(다운빈+미달HBM, -13%).
4. **경쟁 AI 3사** — 관성/점유율집착/자만/손실회피/정치제약 5개 행동편향. 관성만큼 재평가를 건너뛰고
   이전 결정을 유지하다가 현금위기 시 강제 재평가.

## 설계 과정에서 발견한 문제와 수정

최초 구현은 `Sufficiency = 산업 총 Saleable Bit / 수요`를 매 분기 독립적으로 성장하는 두 계열의 비율로
계산했다. 반응함수를 순진하게 매 분기 복리 적용한 결과, 국면이 여러 분기 연속으로 극단에 머무를 때
가격이 10^80 단위로 폭주했다(실측 데이터가 Sufficiency ≈ 0.97~1.03 근방에서만 관찰된 값이라
반응함수도 그 근방에서만 검증됐기 때문). 이를 다음과 같이 재설계했다:

- 정권(상승/하락) 시작 시 **그 정권 전체의 누적 로그수익률**을 캘리브레이션된 중앙값·꼬리 분포에서
  직접 샘플링하고, 정권의 분기 수만큼 균등 분배한다 — 매 분기 공식을 자유롭게 복리 적용하는 대신
  "이 정권은 총 −53.5%짜리 하락이다"를 먼저 정하고 나눠 담는 방식.
  이렇게 하면 정권이 길어져도(최대 12분기) 총 변동폭은 캘리브레이션 값 안에 갇힌다.
  국면상수·반응함수 자체(`priceDelta`)는 그대로 두고, 매 분기 적용된 ΔlnP로부터 역산(이분탐색)해
  Sufficiency/국면 배지를 되돌려 계산하므로 3.2절 공식과 국면 표시는 계속 일치한다.
  플레이어/AI의 실제 증설·가동률 결정은 작은 폭(±)의 추가 가격 압력(`capacityPressure`)으로
  반영해, 인과관계(결정→공급→가격)는 유지하되 정권 목표치를 압도하지 않게 했다.
- 시대(성숙기/성장둔화기/AI슈퍼사이클)는 정권의 방향 확률(`pUp`)과 상승/하락 강도 배율을 다르게
  주는 방식으로 반영했다(§3.4 표의 ASP YoY 방향·크기를 직접적인 가격 함수로 쓰지 않고, 정권
  샘플링을 통해 간접적으로 근사).
- 초기 웨이퍼 원가/고정비 상수도 재보정했다 — 최초 값은 기준가에서 마진이 거의 0이라 어떤 전략도
  가격이 조금만 하락하면 바로 파산했다. 수정 후에도 "성숙기" 프리셋은 의도적으로 매우 가혹하다
  (실측 90년대~2000년대 DRAM 커머디티 붕괴기에 대응하는 난이도 프리셋이며, 실제로 그 시기 다수의
  업체가 파산·합병되었다).

## 몬테카를로 검증 결과 요약 (`node validate.js`, 15시드×5전략×4진영, era=성장둔화기)

- **지배 전략 부재**: 5개 전략 모두 중앙값 스코어가 비슷한 밴드(-1,300 ~ -3,700)에 몰려 있고, 평균은
  분포가 강하게 우편향(가끔 나오는 초호황 시드가 평균을 끌어올림)이라 평균만으로는 격차가 커 보이지만
  중앙값 기준으로는 뚜렷한 지배 전략이 없다. "공격증설"은 중앙값이 가장 낮고(고위험) 최댓값이 가장
  높은(고보상) 전형적 고분산 전략으로 나타난다.
- **진영 균형**: 4개 진영 중 특정 진영이 자기 진영 최고 스코어 우세를 70% 이상 차지하지 않음 (PASS).
- **파산율**: "성장둔화기" 기준 균형형 전략으로 약 40~50%. "성숙기"는 훨씬 가혹(70%대), "AI슈퍼사이클"은
  거의 파산하지 않음(0%대) — 3개 시대 프리셋이 서로 다른 난이도로 기능한다는 의도와 부합한다.
- **노드 전환 타이밍**: 몬테카를로의 5개 전략은 모두 "턴 N의 배수마다 전환"처럼 스크립트로 고정된
  트리거를 쓰기 때문에, 이 수치(T1~T11, 중앙값 T5)는 "실제 플레이어의 고민 시점"이 아니라
  "봇이 버튼을 누른 시점"이다. 아래 항목 참고.

## DoD #2 자가 점검 — 노드 전환 타이밍 긴장

설계상 노드 전환은 12분기(3년) 리드타임 + 전환 직후 2분기 Ramp Valley를 가지며, 티어1(HBM 프리미엄)
게이트는 "업계 리더 대비 1세대 이내"로 상대적으로 정의했다. 즉 경쟁사가 전환할 때마다 게이트 기준
자체가 따라 움직이므로, 한 번 전환해도 몇 년 뒤 다시 뒤처질 수 있다 — 이 상대 게이트가 3~8년차에
걸쳐 반복적으로 "지금 전환할까, 버틸까"를 강제한다. 다만 이는 메커니즘 설계에 근거한 주장이며,
스크립트 전략의 몬테카를로 결과로 직접 실측하지는 못했다(스크립트가 정해진 턴에 기계적으로
전환하기 때문). 실제 사람 플레이테스트로 3~5년차(턴 12~20) 구간에 결정이 몰리는지 확인하는 것을
v0.3 전 과제로 남긴다.

## 알려진 가정·한계 (v0.3 이후 재검토 필요)

- **경쟁 AI 5개 행동편향의 진영별 초기값**은 핸드오프 문서가 "대화 히스토리 또는 사용자에게 재확인"하라고
  명시했으나 원본 v0.3 5절 수치를 확보하지 못해, 각 진영의 알려진 실제 성향(SK하이닉스=HBM 공격적,
  삼성=점유율 방어, 마이크론=재무 보수적, CXMT=정치적 제약 강함)에 기반해 임의로 초기값을 설정했다.
  실측 근거는 없다.
- 노드별 Gross Bit/Wafer, 웨이퍼 원가, SG&A 등 재무 상수는 방향성만 반영한 추정값이며, 설계 문서
  8절이 명시한 대로 정밀 캘리브레이션은 보류 상태다.
- "국내고객 매출비중"(CXMT KPI)은 실제 고객 지역 데이터가 없어 티어3(채널) 매출 비중으로 근사했다.
